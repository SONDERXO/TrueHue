# Saved-trace audit of clean-photo failures

7 November 2026. User resumes correction-model development. This step audits
existing artifacts only; it does not authorize another fit, feature sweep,
threshold adjustment, new dataset, annotation or app/model adoption.

## Question

Why can the clean-constrained affine gate protect its fitting clean examples
yet apply harmful controls to unseen clean photos? Separate the gate's mistaken
action from the damage caused by the already-saved correction controls.

## Frozen inputs and scope

Use the completed clean-constrained gate models/comparison, the original
split-benefit training traces, whole-scene prepared row identities and frozen
full-model gate feature table. All data are already development-exposed.
Preliminary saved-result inspection identified the existing7/29 and3/23 clean
failures and two severe errors. This is a retrospective diagnosis, not a blind
evaluation or a new predeclared acceptance test.

Analyze every available clean query in the working256 held-group suite and the
later fallback-native224 suite:29+23=52photos with features. Preserve the two
unavailable clean attempts. Do not count the duplicated borrowed/input/fallback
native clean records as independent images. Recompute all available saved gate
scores in these two suites as an independent arithmetic replay.

For each clean query, choose its nearest fitting clean vector using Euclidean
distance in that gate's frozen standardized12-feature coordinates. This is a
fixed descriptive reference, not a new action rule or a fitted nearest-neighbour
classifier. Audit training-row/held-group exclusion and all fitting constraints.

Decompose the query score into nearest-clean score plus12 exact weighted feature
differences. Report facial versus scene sums, strongest positive terms, whether
the query is inside individual fitting-clean feature ranges, saved controls,
predicted benefit, actual saved reconstruction loss and retained-gate decision.
Record fitted-clean versus query feature provenance; nearest distances are
diagnostic geometry, not probabilities or proof of adequate coverage.

Summarize all clean rows, changed-case overlap with the retained gate, error
concentration and brightness versus colour deviations. Inspect the existing
boards of the worst clean error in each suite and the later failed clean case
nearest to fitting clean support. Outcome-based visual selection is explicit.

## Verification and stop

Check feature order, training trace/case alignment, no held-key fitting membership,
290repeated fitting clean constraint occurrences, saved score/action replay,
nearest-reference reconstruction identities, original input hashes and preserved
comparison totals. No image-model forward, new correction rendering, reference
label, predictive fit or data selection is created. Store individual case details
privately; publish only aggregate findings and supported limitations in docs.

End with one justified proposed next experiment, if evidence warrants one. Any
new fit remains subject to a separately agreed bounded protocol. A feature's
large score contribution is not proof that deleting it will repair generalization.
