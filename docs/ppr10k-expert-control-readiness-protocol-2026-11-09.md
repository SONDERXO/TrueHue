# Expert-target identity-control readiness protocol — 9 November 2026

## Design and authorisation

User retains the decision tree and authorises continuing the training-evidence
review, following the standing instruction to make sustained justified progress.
This is one bounded data-readiness check, not a new correction learning cycle.
It tests missing expert-reference measurements for potential photographic
supervision. No new input feature family, predictor, crop policy, action library
or numerical acceptance threshold is introduced.

The exact eight editor-A targets correspond to the existing eight source frames:
787_0,330_0,767_0,1117_0,1188_0,990_0,904_0,455_0, in frozen order. Use the existing
original TIFFs; no new editor, image, augmentation, annotation batch or download.
Keep all eight outcomes. The source904_0 wrong-person failure and source1188_0
fragmentation remain independently recorded, regardless of target success.

## Meaning of an identity control

The selected expert rendition is the declared photographic target. A target-to-
itself training control would request identity by definition; this is not proof
that the photo has physically correct skin colour, is universally preferred, or
has a validated mask. No target control is admitted until input processing,
source/target person linkage, role grouping and feature compatibility are assessed.
Source features must never be substituted for target features. At eventual app
inference, a reference is unavailable; no paired-reference difference may enter
the tree. No tree is fitted here.

## Fixed processing

Preflight all sixteen original inherited hashes/types/dimensions/sRGB profiles,
the native-coordinate contract, prior source-diagnostic/verification bindings,
the exact existing models/helper code and this protocol. Exclusive new output
directory, refuse overwrite and preserve partial results. Original RGB8 target
samples are used unchanged, converted to BGR for inference; never divide them
by257. Original sourceRGB16 remains unchanged and is not newly inferred.

For each target: exactly one full native-size YuNet anchor call at .85/NMS.3/
topK5000. Preserve zero/multiple faces as failures; no manual person selection.
If exactly one is returned, use the same native1.5square bridge and at most one
existing parent pipeline invocation. Maximum16detector calls (8anchors+8parents),
8dense-parser and8FaceOcc calls. Record landmark-helper attempts including existing
fallbacks. No new thresholds, detector/parser alternatives or enhanced appearance.

Same nostril/visibility guard, normalized1000pixels, uncertain-glasses protection,
face/visible-neck support and identity parameters as the source diagnostic.
Save the target's own four raw Lab/ITA values if available; no MST label/mapping
invented or calibration copied. No correction model or oracle/action-cost fit.

## Independent checks and review

Verify exact target slices, mask/projection/alpha/protection/identity and input/
artifact hashes without additional model calls. Review all available boards and
all native anchor overlays; retain failures. Compare target person visually to
the historical source-only locator and the source diagnostic selection. The
source904 failure is not cured by choosing either target person. Record raw
technical availability separately from paired intended-person readiness.

Report source/target measurement/support differences descriptively. They include
different detection/crop/mask selection and do not isolate editor colour changes.
No matching-threshold tuning, dense mask score or new training-admission cutoff.
The target-to-itself identity renderer is a software invariant, not evidence that
a learned tree would preserve clean photographs.

## Stop

After all eight or a contract/execution failure, close the check. No automatic
parser/crop/threshold rescue, extra editor, clean-control fabrication, favourable-
subset fit, cost/action change or new MST/calibration. Data-role and feature/
evaluation compatibility still require review before any tree comparison. Old
joint gates and failed results remain intact. Final8group/24photo holdout stays
byte-unread; no runtime changes, contact, upload, commit or push.
